# OpenAI

> [!IMPORTANT]
> Версия 1.0 — это масштабное переписывание рантайма плагина, каталога моделей и набора тестов.
> Она заменяет базовую логику запросов и стриминга, убирает устаревшие конфигурации моделей и добавляет прицельное покрытие для рассуждений (reasoning), вызовов инструментов, мультимодального ввода и чередующихся потоков.

Этот плагин подключает Arkady к языковым, эмбеддинговым, модерационным моделям OpenAI, а также к моделям речь-в-текст и текст-в-речь.

## Что изменилось в 1.0

- Интеграция LLM переписана на основе официального Python SDK OpenAI.
- Responses API теперь используется по умолчанию для поддерживаемых языковых моделей.
- Chat Completions по-прежнему доступен для совместимых эндпоинтов и чат-моделей с поддержкой аудио.
- Восстановление состояния рассуждений (stateless reasoning replay) сохраняет все выходные элементы OpenAI, включая зашифрованные элементы рассуждений и метаданные фазы ассистента.
- Сводки рассуждений, отказы, параллельные вызовы функций, терминальные состояния, учёт использования и отмена стрима теперь обрабатываются явно.
- Каталог моделей сверен с документацией OpenAI по моделям и их устареванию.
- Устаревшие и недоступные записи моделей удалены, отсутствовавшие актуальные — добавлены.
- Устаревшие алиасы `gpt-4o`, `gpt-audio-mini` и `gpt-4o-mini-tts` удалены, при этом их всё ещё актуальные датированные снапшоты остаются доступны.
- Тесты реорганизованы в параметризованные наборы pytest с покрытием запросов, ответов, стриминга и граничных случаев не-LLM функциональности.

## Возможности

- Генерация текста и обработка изображений (vision).
- Структурированные ответы и вызов функций.
- Управление усилием рассуждений, сводками, режимами и контекстом — там, где это поддерживается выбранной моделью.
- Ввод изображений и документов через URL или base64 в Responses API.
- Аудио-ввод через поддерживаемые модели Chat Completions.
- Текстовые эмбеддинги.
- Модерация текста через `omni-moderation-latest`.
- Транскрибация речи и стриминг текст-в-речь.

## Настройка

Установите плагин и откройте провайдера OpenAI в настройках Model Provider в Arkady.

Добавьте API-ключ OpenAI и при необходимости — Organization ID или собственный базовый URL API.

Базовый URL можно указывать как с завершающим `/v1`, так и без него.

Responses — рекомендуемый протокол, используется по умолчанию для официальных моделей, которые его поддерживают.

Выбирайте Chat Completions только для совместимого эндпоинта или модели, документированный API которой этого требует.

`Enable request metadata` — опция, отключена по умолчанию. При включении к каждому запросу в качестве `metadata` прикрепляются `arkady_app_id` и `arkady_source`, что позволяет атрибутировать использование к конкретному приложению Arkady.

API принимает metadata только при включённом хранении, поэтому включение этой опции также отправляет `store=true`, что сохраняет запросы и ответы в Stored Completions вашего аккаунта OpenAI. Оставьте её выключенной, если ваша организация запрещает хранение данных или вы работаете через прокси, отклоняющий `store` или `metadata`.

## Состояние рассуждений (reasoning)

По умолчанию плагин отправляет `store=false` и запрашивает зашифрованное содержимое рассуждений при использовании Responses API. Включение `Enable request metadata` переключает `store` на `true`, но зашифрованное содержимое рассуждений всё равно запрашивается, поэтому восстановление состояния рассуждений ведёт себя одинаково в обоих случаях.

Полные элементы вывода ответа сохраняются в непрозрачном (opaque) payload сообщения ассистента и воспроизводятся в исходном порядке на следующем ходе.

Сводки рассуждений видны пользователю только если для поддерживаемой модели включена опция `reasoning_summary`.

OpenAI может потребовать верификацию организации перед тем, как возвращать сводки рассуждений.

## Разработка

Установите зафиксированное окружение и запустите проверки из этой директории.

```bash
uv sync --locked
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

### Тесты на реальном API OpenAI

Тесты в `tests/live` отправляют платные запросы к реальному API OpenAI, когда доступен непустой `OPENAI_API_KEY`.

Они пропускаются динамически только если ключ отсутствует, пуст или состоит из пробелов — как в `.env`, так и в переменных окружения процесса.

Создайте локальный `.env` в директории этого плагина для тестовых учётных данных.

```dotenv
OPENAI_API_KEY=your-api-key
# OPENAI_ORGANIZATION=org-id
# OPENAI_BASE_URL=https://api.openai.com/v1
```

Тестовый харнесс читает из `.env` только эти переменные OpenAI, а явные переменные окружения процесса имеют приоритет.

Репозиторий игнорирует `.env` — никогда не коммитьте его и не включайте его значения в вывод тестов.

Запуск полной матрицы тестов.

```bash
uv run pytest tests/live
```

Полная матрица отправляет по одному логическому запросу для каждой настроенной модели плюс прицельные граничные запросы, а сценарий воспроизведения инструментов отправляет второй запрос.

SDK OpenAI может повторять временные сбои, поэтому фактическое число HTTP-попыток может превышать количество логических запросов.

Матрицу следует запускать последовательно, поскольку параллельное выполнение увеличивает и расходы, и нагрузку на rate-limit.

Используйте стандартные идентификаторы узлов pytest или выражения `-k`, чтобы сузить матрицу во время разработки.

Следующая команда для быстрой проверки отправляет один короткий запрос.

```bash
uv run pytest \
  'tests/live/test_llm.py::test_every_presented_llm_accepts_a_minimal_request[gpt-4o-mini]'
```

Презентационная матрица отправляет по одному минимальному запросу для каждой LLM из `models/llm/_position.yaml`, используя стриминг там, где это поддерживается контрактом модели.

Тесты эмбеддингов, модерации, речь-в-текст и текст-в-речь генерируются из каждой YAML-конфигурации в соответствующих директориях моделей.

Отдельные репрезентативные модели покрывают Responses и Chat Completions, стриминг и его отсутствие, структурированный вывод, сводки рассуждений, стримингуемые вызовы функций, воспроизведение зашифрованных рассуждений, состояния остановки и незавершённости, а также ввод изображений, документов и аудио.

Точные чередования событий, фрагментированные аргументы инструментов, пустые блоки рассуждений, сбои, отмена и некорректно сформированные ответы остаются в детерминированных модульных тестах, поскольку живой сервис не может надёжно воспроизвести такой порядок событий.

Случаи, заблокированные только верификацией организации OpenAI, отмечаются как пропущенные (skip); все прочие ошибки API проваливают прогон.

Покрытие сводок рассуждений тоже может пропускаться, если OpenAI принимает запрос, но не отдаёт сводку неверифицированной организации.
